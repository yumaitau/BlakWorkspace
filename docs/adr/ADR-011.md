# ADR-011: Hermes as opt-in sovereign AI runtime

- Status: Accepted
- Date: 2026-09-19

## Context

Blak Workspace keeps AI processing of customer content **off by default** (assumption 9, BW-053). Operators still need a documented runtime that can sit beside Drive, Docs, and Knowledge, answer from those stores, and stay inside the one-organisation deployment boundary. YumaOS already packages [Hermes Agent](https://github.com/nousresearch/hermes-agent) as `ghcr.io/yumaitau/companyos-hermes`: cluster-local gateway, no published ports, MCP into the product control plane.

This overlay does not embed OpenAI/Anthropic as the Blak default. Inference provider is owner-chosen (local or AU-resident). External SaaS inference is an explicit extra flag, not a silent default.

## Decision

- **Blak Hermes** is the product label. Internal id stays `hermes`.
- Default eval/staging/prod profiles leave Hermes **disabled**. Document search is a second opt-in (`hermes.documentSearch`).
- When search is on, the corpus is Blak Drive (Nextcloud), Blak Docs (Collabora files on Drive), and Blak Knowledge (Docmost). XWiki is not a corpus backend.
- Control plane is **Nubus**. The gateway (8642) and dashboard (9119) stay cluster-local. Browsers talk through an authenticated portal/proxy, never a public Hermes port. MCP path is `/api/hermes/mcp`.
- Isolation is the deployment: one Hermes per customer organisation, same as ADR-002. Hermes itself is not multi-tenant.
- `allowPublicUnauthenticated` and `publishGateway` are forbidden. Validation fails the tree if they are true.
- Image tag/digest is TBD until pinned. Do not invent digests. Licence recorded as TBD in THIRD_PARTY_NOTICES.
- This is not an IRAP, PROTECTED, or sovereignty certification claim.

## Consequences

Operators can deploy Hermes alongside the overlay without turning on AI for every tenant. Search across workplace documents is possible only after two explicit flags and Nubus SSO. Live smoke still needs an eval cluster and identity work (BW-019/BW-020).
