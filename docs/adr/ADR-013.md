# ADR-013: Terraform + Helm standup for K3s and EKS

- Status: Accepted
- Date: 2026-09-19

## Context

The overlay seed had profile flags and a Sites chart stub but no cluster path. Operators need to stand the suite up on a local box (K3s) or on EKS without forking openDesk's 35+ Helm charts. Upstream deploys via Helmfile from pin `v1.18.2`. CI must not apply infrastructure. Image digests stay uninvented. openDesk eval hardware is ~12 CPU / 32 GiB and amd64-only.

## Decision

- **Terraform** provisions the cluster and cluster add-ons; **Helmfile** still installs openDesk; **Helm** installs add-ons (ingress-nginx 4.11.5, cert-manager v1.16.2) and Blak sidecars when an image tag is pinned.
- Default target is **k3s via k3d** on a local box. EKS is a separate root (`deploy/terraform/eks`) gated by `allow_paid_cloud`.
- `scripts/blak_deploy.py` is the planner Terraform calls (`data.external`). It refuses prod apply, EKS without the paid flag, suite apply without an openDesk checkout and `MASTER_PASSWORD`, and Sites install while `imageTag` is `TBD`.
- GitHub Actions `validate` still must not contain `terraform apply` or `helmfile apply`.
- Do not vendor openDesk charts. Fetch the pin; copy generated Blak values into the checkout's `dev` environment at apply time only.

## Consequences

A box with Docker/k3d can `terraform apply -var-file=examples/k3s.tfvars` and get a cluster plus ingress. Full Drive/Chat/Meet still needs the openDesk checkout, RAM, and amd64. Apple Silicon may fail suite image pulls. Paid EKS is opt-in. This is not an IRAP/PROTECTED claim and does not apply production.
