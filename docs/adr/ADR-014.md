# ADR-014: Pivot from openDesk distribution to modular Blak platform

- Status: Accepted
- Date: 2026-09-19

## Context

Blak Workspace seeded as branding/config overlay on a full openDesk suite (bundled identity, file sync, wiki, mail, video, projects). That forces small orgs (10–20 users, 2–4 Lenovo Tiny/SFF) to carry mail, video, and project stacks they may not need. Kubernetes mandatory, heavy identity, fork risk per app.

Target: lightweight, modular, sovereign workplace with M365/Google-like capabilities via small replaceable OSS components behind one Blak UX. K8s optional for small. AI optional. Reuse customer mail/meet.

## Decision

1. Blak Portal (Next.js) owns UX: Home, Drive, Docs, Sites, Projects, Forms, Chat, Meet, AI. Backends replaceable via adapters.
2. Base = Portal + Identity + Drive + Docs + Sites + Search + Admin + Audit. No mail, no Jitsi, no OpenProject by default.
3. Drive: OpenCloud. Docs: Collabora retained. Sites: Docmost (not XWiki). Projects: Plane optional.
4. Identity: Authentik or Keycloak standalone. No full Nubus unless justified. OIDC-first, Entra/LDAP/AD/SAML federation, SCIM where possible.
5. Mail/Meet = integration layers (M365, Google, IMAP/SMTP; Teams/Meet/Jitsi). Self-hosted mail/Jitsi optional modules only.
6. Chat optional behind `ChatProvider` (Matrix lighter homeserver / Mattermost / Element).
7. Cross-cutting: Postgres shared cluster (logical DBs), Valkey/Redis, S3 abstraction (MinIO/SeaweedFS/sovereign S3), NATS/Redis Streams events (no Kafka), Meilisearch/OpenSearch, central notifications + audit, OpenAI-compatible AI Gateway.
8. Deploy: Docker Compose (Micro/Small) + K3s/Helm (Business/Enterprise). Same containers both models. Profiles: Micro (5–20, 1–2 nodes), Small (20–100, 3 Tiny), Business (100–500, K3s), Enterprise/Gov (PSPF/ISM-aligned, air-gap feasible).
9. Upstream strategy: adapter over fork. `Upstream → Adapter → Blak API → Blak UI`. Interfaces: Storage, Document, Identity, Knowledge, Project, Chat, Meeting, AI, Search.

## Consequences

- Keep openDesk pin as reference only; no new openDesk feature work.
- Must build Portal, adapters, gateway/search/notifications/audit services.
- Migration path for existing overlay work: branding → Portal theme package; Docmost work retained; Drive specifics isolated to adapter.
- Small deploys get simpler; large deploys add HA later.
