# [BW-002] Pin openDesk upstream baseline

## Problem / outcome
Deploy overlays must pin a known openDesk release for reproducible branding and config work.

## Context / upstream evidence
Discovery 2026-09-18 recorded openDesk v1.18.2 commit eab2ee774187308f82307f0daaf1471dfe560f34 (2026-09-11) at https://gitlab.opencode.de/bmi/opendesk/deployment/opendesk. Parallel line v1.17.4 commit 21c590d8f684d916be80ba00728fb02ef6c1250b (2026-09-15). Docs at https://docs.opendesk.eu/operations/. Image digests live in helmfile/environments/default/images.yaml.gotmpl. Never invent digests.

This issue is part of epic BW-E01 under milestone M0. Work should stay within the Blak Workspace overlay model: branding, configuration, deploy automation, documentation, and carefully scoped extensions on openDesk. Preserve upstream compatibility. Prefer `upstream:configuration` over `upstream:patch`. Australian English for human docs. Do not invent community endorsements, cultural assets, PROTECTED/IRAP claims, or Microsoft 365 parity.

Operators and contributors should treat the acceptance criteria as the definition of done for this seed stage. If upstream evidence changes (new openDesk tag, theming hook, or identity behaviour), update docs/upstream-baseline.md and related ADRs rather than quietly drifting. Licence impact for this item is recorded as `none`; apply `needs:licence-review` when redistribution or copyleft enablement is affected. Cultural or community-facing copy must use `needs:cultural-review`.

Related assumptions include one customer organisation per deployment, Kubernetes with supported Helm/Helmfile, unbranded baseline then Blak overlay, eval/staging/prod profiles, AU hosting intent without paid infra in this seed run, en-AU locale, Nubus identity start, optional Entra investigation only, core pilot workflow focus, Docmost for Blak Knowledge (BW-055), and AI off by default for customer content.
