# [BW-055] Replace XWiki with Docmost for Blak Knowledge

## Problem / outcome
Blak Knowledge must not ship on XWiki. Docmost is the chosen knowledge base for the Blak overlay so operators get a modern, licence-clearer wiki experience that fits the Indigenous-branded workplace without carrying XWiki operational and licence weight by default.

## Context / upstream evidence
openDesk includes XWiki (LGPL-2.1-or-later) as the knowledge management application. Blak Workspace is an overlay distribution: branding, config, deploy automation, docs, and carefully scoped extensions. Replacing XWiki with Docmost is an intentional product decision for Blak Knowledge labelling and default profiles. Upstream compatibility for other openDesk apps must still be preserved. Do not invent Docmost digests; pin a real release when integrating. Coordinate with BW-034 (Notes/Knowledge enablement) so XWiki paths are superseded rather than dual-enabled.

This issue is part of epic BW-E06 under milestone M3. Prefer upstream:configuration where Docmost can be added as a replaced component profile. Australian English. No fabricated cultural assets or certification claims. Licence impact high until THIRD_PARTY lists Docmost accurately. Apply needs:licence-review when redistributing Docmost artefacts.

Related assumptions: one customer organisation per deployment; Kubernetes with supported Helm/Helmfile; Docmost for Blak Knowledge (not XWiki); AI off by default.

## In scope
- Product decision recorded: Blak Knowledge = Docmost, not XWiki
- Default profiles disable XWiki and do not enable XWiki alongside Docmost
- Deployment overlay stubs and docs for Docmost enablement path
